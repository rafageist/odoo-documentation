# Glossary

## Purpose
- This branch explains business vocabulary that developers repeatedly encounter in Odoo code, specs, tickets, and implementations.
- The goal is not to replace module or model notes, but to bridge business meaning with the technical objects that implement it.
- Use these notes as the semantic entry point when a requirement is written in business language but the implementation lives in models, views, routes, or workflows.

## How to use it
- Start here when a term appears in a ticket, functional discussion, or customer requirement and you need to map it to the right model or module.
- Follow the related links to `Core`, `Community Addons`, `Enterprise Addons`, and adjacent glossary terms.
- Keep glossary notes short, precise, and cross-linked. The detail should live in canonical technical notes.
